# Architecture

`src/chess` owns serializable studies and legal history. Nodes have stable IDs, parent/children links, FEN snapshots, comments, and annotations. The explicit original mainline remains separate from selected branches. chess.js validates/replays moves; @mliebelt/pgn-parser parses recursive PGN syntax.

`src/engine` owns UCI parsing and a serialized worker queue. Requests carry root FEN plus complete history. Abort drains the old job or recreates an unresponsive worker; completion uses a consistent-depth set of exact principal variations. Scores normalize to White's perspective once. Full and Lite builds are explicitly selected and engine identity is checked. Asset URLs include an immutable checksum-derived build identifier.

`src/review` compares best and played moves from the same root, creates classifications, records legal tactical evidence, and computes original-mainline reports. `src/coach` maps this evidence to text/actions. `src/retry` creates isolated attempts; saving a branch is explicit. No report reads retry or sideline moves into original-game accuracy.

`src/board` renders positions and square-based overlays; it knows nothing about review scheduling. User, engine, and coach layers remain distinct. Board orientation affects rendering rather than stored coordinates.

`src/storage` stores studies, preferences, and disposable analysis records in IndexedDB. Saves are transactional and stale revisions cannot overwrite newer ones. Backup validation replays every branch before import. Restoring ID collisions creates copies rather than silently discarding either version.

`src/offline` verifies engine assets by SHA-256 before committing an offline-ready set. The production service worker precaches the application and opening data, and routes engine requests to an explicitly matching build. User studies are never stored in, or removed with, asset caches. App updates wait for user action after a successful save.

`src/app/WorkspaceApp` provides the persistent three-mode sidebar and mounts one workspace at a time so review and opponent workers do not compete. Review state is saved before switching modes. `ModeBoard`, `BoardTools`, and `BoardNavigation` provide the same board frame and controls to all modes; `workspace.css` owns their shared geometry and caps the desktop control panel at 360px. The review surface is bounded by the viewport, moves are paginated, and Settings holds scrollable secondary content. `src/app` coordinates UI state and feature controllers. Temporary demonstrations and retries own their positions without changing the study cursor. Displayed engine results must match the selected root/history even when engine analysis is paused.

`src/training/OpeningTeacher` chooses between the new course workspace and saved custom/short lessons. `CourseWelcome` makes complete courses the default entry. `OpeningLibrary` separates Courses, Learned, My repertoires, Single lines, and Import PGN. `PickerCombobox` provides the shared compact keyboard-accessible search interaction. The opening library and full explanations use scrollable dialogs; the main teacher screen stays within the viewport.

`src/training/courses` compiles immutable opening-catalog snapshots into canonical opening courses. London System aliases are grouped across database families. `unique-lines` keeps only the longest legal UCI sequences for each root, absorbing aliases and shorter prefixes before depth-first ordering the complete available continuations; PGN imports use the same rule. Named opening branches form contiguous sections, with nearby full lines taught together rather than per-move prefixes. Parsing and compilation are cached by input identity. `src/openings/catalog` loads the bundled Lichess TSV data, which the service worker precaches.

`src/training/curriculum` owns the pure full-line guide → plans → batch drill → section review → feedback state machine. Course sections use named opening branches; move-tree traversal finishes a longest continuation before its nearby alternatives, for either player. `practice-batches` divides each section into contiguous batches of at most five variations, with a four-extra-half-move budget measured against the nearest line already in that batch. The learner finishes all batch lessons before a shuffled batch drill. After the final batch, a freshly shuffled section drill includes every section variation, even when there are more than five. Each scheduled drill has a stable kind/batch-or-section-end/variation score slot: 10 for a clean completion, 5 after any mistake; retry updates the maximum rather than adding duplicate points. Hints are explicit and tracked without a points penalty. Learner and opponent moves advance one ply at a time in both session models. Guided lessons accept manual input for either color and wait at every position, including White’s opening move for Black courses. Only recall drills schedule automatic opponent moves after 500ms, giving each move its own board animation. `useMoveKeyPacing` limits held-arrow repeats to one step per 500ms after any position change in teachers and game review; separate key presses stay immediate. `MoveThought` anchors compact first-person explanations of legal move effects to the last played piece (or the first piece before starting), mirrors board orientation, and stays hidden in recall drills. Each explanation returns square marks alongside its selected thought sentence, reusing board annotations with blue for control/defense, red for attack/capture, and green for movement. Teachers show only the current bubble’s marks, including the final move; mostly opaque glass styling keeps the text legible with a subtle view of the board behind the cloud. Timers cancel for dialogs, inactive workspaces, or conflicts; lesson navigation never starts an automatic reply. Saved drills can wait on an opponent turn and resume that reply. A validated per-course library in localStorage stores the course snapshot, round order, position, attempts, and scores; the active line is compiled lazily. Reads migrate the earlier single-course envelope. Saves merge independent courses, reject stale same-course snapshots, and preserve existing data on validation/quota failures. The UI locks a conflicting attempt and offers to load the saved version.

`course-progress` derives learning history from the current score ledger and carried exact-line recalls. Unique variations with completed drills count as learned; complete section-review ledgers mark a completed course even after a restart. Legacy final cumulative-round ledgers also remain recognizable. `useSavedCourses` reads all validated course snapshots and refreshes on storage events or window focus. The Learned view can resume saved snapshots without a loaded catalog. `CourseSyllabus` shares expandable sections and variation statuses between course browsing and the lesson progress dialog. The opening chooser has one bounded content scroller below its persistent title and tabs.

Old course queues remain readable and finish in their saved order. Changed catalog syllabuses upgrade atomically against the old course and session: indexed awards become carried points and recall history keyed by the exact root and UCI sequence, and learning starts at the rebuilt full-line syllabus. A recalled shorter prefix does not mark its longer replacement as learned. Restarts retain both carried history and current best scores. Longest-line compaction applies when building catalog courses, PGN imports, and repertoire practice packs. Editable repertoire membership is preserved even when its practice pack absorbs shorter prefixes.

`src/training/explanations` derives legal board facts for each move, adds guarded opening-family themes, and describes conditional middlegame plans from the final position and training side. It does not invoke an AI service or invent engine-ranked continuations. The compact panel shows the next guided move; dialogs expose full explanations and plans. Drill UI keeps this content and coach arrows hidden unless a hint is requested.

`LegacyOpeningTeacher`, `session`, and `packs` preserve the earlier authored packs and custom PGN/repertoire scheduler. Their progress key is independent of the new curriculum library. `src/training/repertoires` stores named White/Black collections separately, validates legal lines, deduplicates move sequences, and compiles collections into `OpeningPack` lessons. Its saves reject stale snapshots from another tab. `src/openings/families` still provides browsing groups for the advanced single-line picker.

`src/play` owns the opponent-game model and a separate UCI client. Each game has independent strength settings; the client returns UCI `bestmove` instead of inferring it from principal variations. Canceled workers are disposed so late replies cannot enter a new game. A separate `viewPly` cursor browses history without changing the live study cursor or engine input; null follows the live game. Drawings are stored per ply so they survive reconstruction with new node IDs. Validated legal history and settings are saved locally, and completed games become independent review snapshots with fresh study IDs, preserving earlier reviews. Play-session revisions also survive reload. Full-strength review uses its original independent client.
